# Historical Spaces verification — 2026-10-22

This is a historical record of the individually identified candidates below.
The on-demand drawer, dark/light review, and final-build evidence are recorded
in [Spaces drawer verification](2026-10-22-spaces-drawer.md). Earlier results
here do not certify that later binary.

The C++ implementation adds named spaces spanning all connected outputs. Each
space has its own workspace numbers, normal and special workspaces, remembered
output selections and pin intent. A number identifies one workspace within its
space across all monitors. Switching spaces uses the connected outputs without
changing monitor enablement. Populated-space deletion transfers its workspaces
to the selected destination while preserving native windows and layouts.

The recorded Spaces and selector suites, host checks and performance gates passed
on their identified historical candidates.
Broader regression evidence below spans the recorded candidates and focused
helper runs. This record does not claim a single complete `--only all` or full
zoom-driver pass.

**Subsequent revision:** Historical space-aware desktop slider and selector
evidence is appended in “Bar integration revision evidence”. The later drawer
supersedes the always-visible rail and its captures; consult the linked drawer

## Behavior verified

- A single Default space preserves existing native numeric workspace IDs and
  can be renamed. Independent spaces reuse local numbers 1, 3, 5 and 7 with
  distinct native identities; switching changes every output together.
- Ordinary numeric, relative, previous and named workspace dispatchers,
  persistent monitor assignments and application workspace rules resolve in
  the active space. A collected Default workspace retains its UUID when rebuilt
  after a new `defaultName` rule changes its display name. Repeated range rules
  assigning the same `defaultName` preserve separate workspace UUIDs, unique
  logical labels and a valid saved graph.
- Identically named special workspaces and desired pin state remain with their
  owner space. Collected and reused special native IDs retain the correct new
  logical owner. An actual plugin unmap/reload preserves workspace identities,
  native window placement and an inactive space's desired pin state.
- Each output retains its exact normal-workspace UUID across removal,
  switching with fewer outputs, reconnection and config reload. The artifact
  `spaces-hotplug-selections.json` records the before/after selections.
- A second, genuinely new compositor receives the persisted state before plugin
  startup. It restores the saved non-Default space and all three output
  selections; its first new client opens in that space. Space metadata and
  selections persist independently of application process lifetime.
- Delayed overview launches and ordinary desktop execution retain their source
  space after switching, without revealing the delayed window or stealing focus.
- Moving a selected window leaves the current space active. Whole-workspace
  moves and populated-space deletion retain native workspace identities,
  application addresses and layouts. Default can be deleted into another space;
  the final remaining space is protected.

The pure model/store checks cover UUID and UTF-8 name validation, duplicate local
and native identities, sparse-number transfer collisions, named/special name
collisions, monitor references, optional pin metadata, unsupported state versions,
atomic backup recovery, immutable worker snapshots, coalesced writes, shutdown
draining and write failures. The store writes versioned JSON under
`$XDG_STATE_HOME/hyprspace/spaces.json`, with the standard home-directory fallback.

## Performance run conditions and failed attempt

The fresh baseline and final candidate ran sequentially after this work's other
builds and private test sessions finished. An initial final-candidate attempt
`/tmp/hs-i.ozjca_r8` timed out after the 36-window overview stress case while
preparing the next 3-window board case: `hyprctl -j clients` exceeded its
10-second IPC timeout. Its completed 3- and 12-window overview input p95 values
were 18.00 ms and 17.94 ms; the 36-window stress value was 62.70 ms. This attempt
retains its timed-out status.

Kernel evidence in `/tmp/hs-i.ozjca_r8/kernel-oom.txt` records a system-wide
out-of-memory event at 19:04:20–19:04:22 during that attempt: Chromium invoked the
OOM killer and a Chromium process was killed. Subsequent failure capture could
query the compositor and recorded a closed overlay, released capture/texture
bytes and one newly mapped client. The run was environmentally contaminated;
the exact internal cause of the IPC stall has not been established.

The unchanged candidate then passed all 13 performance checks. Its one-second
host load/PSI/vmstat sampler records load average falling from 21.77 to 8.61,
6,376 swap-in pages, 5,234 swap-out pages and 8,353 major faults. Timeout-only
process/stack capture was not invoked on this successful run. The sampled
memory pressure and recent OOM prevent describing the host as idle.

An earlier intermediate performance report `/tmp/hs-i._173kdo8` is retained for
audit. Its paired 12-window-board render comparison exceeded the limit while
other private tests overlapped. The final candidate passes comparisons against
both the fresh baseline and the original retained baseline; no timing change is
attributed to a particular code change from these observations.

## Bar integration revision evidence

The visible workspace pill is the existing Rust `workspaces-slider` layer
surface, managed by `workspaces-slider.service`. It is separate from Waybar;
its two installed processes are the supervisor and an output child. User
Waybar config and styling remain unchanged. `~/.config/waybar` resolves through
GNU Stow to `~/dotfiles/waybar/.config/waybar`, where the maintained slider source
lives in `workspaces-slider-rs`.

The adapter now reads the lightweight active-space snapshot, maps local numbers
to the existing ten slots and monitor colors, and carries the displayed space
UUID in each click or relative scroll request. Missing or unsupported metadata
clears occupancy and selection and disables clicks. State I/O runs in the event
worker; there is no periodic workspace polling. The supervisor retains its
child-health timer while refreshing monitor metadata only at startup, after
output changes or after config reload. Namespace transitions reset partial wheel gestures and prior
animation state. Commands use a bounded FIFO to preserve ordering and cap pending work. Existing rendering and service wiring are retained.
